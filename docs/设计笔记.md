# 她是怎么跑起来的 · 工程笔记

> 这里只写思路和踩过的坑，不放源码（源码里有密钥和私有设定）。

## 1. 为什么不用现成的聊天机器人框架

试过直接用现成框架接大模型，问题是：**人格守不住**。

模型会顺着上下文越来越"热情"，聊几轮就开始自我介绍、编造经历、承诺做不到的事。
把规矩写进提示词里只能压一阵子，压不住长期。

所以最后的结构是：**人格放提示词，底线放代码**。

## 2. 三条流水线

**收消息**

OneBot 上报是"一条一条"来的，但人在 QQ 上是连着打好几条。
所以先做合并窗口：同一个人的连续消息攒一小会儿合成一次请求，顺带把重复上报去重。
群聊里只在她被 @ 或者聊到她时才进模型。

**调模型**

走一个 headless agent 子进程，stdin 喂任务、stdout 读 JSON 事件流。
每轮结束会有一个 `step_end` 事件带着这一轮的 token 用量 —— 记账就靠它，比事后去查账单准。

**发出去之前**

出话前过一遍规则闸门。闸门是纯函数：输入（她准备说的话 + 上下文），输出（放行 / 改写 / 拦下）。
纯函数的好处是能写单测 —— 每次线上翻车，就把那句原话抄成一条测试用例，以后不许再犯。

## 3. 记账：只算她自己的

坑在于：同一台机器上还可能跑着别的会话（我自己用的、别的机器人），
如果按"账户余额掉了多少"来记账，就会把别人的开销算到她头上。

所以改成**只读她自己的桥日志**里的用量行：脚本记住上次读到哪个字节偏移，
每次只读增量，按模型价格折算成钱，再乘一个倍率扣她的余额。
谁花的钱算谁的，一点都不串。

余额和真实成本是两本账：
客户充进来的是"面值余额"，其中一部分是留给我的分成，另一部分是真正要回充到模型账户的成本底数。
她消耗的时候按倍率扣余额，分成同步入我的账。

## 4. 看过的作品

她跟人聊完一个作品，代码会把标题写进人设文件里一个带标记的区块：

```
<!-- 看过的作品:BEGIN -->
...
<!-- 看过的作品:END -->
```

提示词拼装时把这块带上，于是下次聊到同一个作品她就有记忆。
这个区块**只能由代码写**，手工改会被下一次覆盖 —— 这类"代码和人共用一个文件"的地方，
一定要有明确的归属，否则迟早互相打架。

## 5. 主动说话

她不只是被动回复，每 30 分钟会自己去发一条 QQ 空间，也会按时间找人说句话。

主动行为比回复危险得多：回复最多是答得不好，主动开口可能变成刷屏。
所以主动那条路上加了三层：冷却时间、每小时上限、深夜静默。
另外还有一条"跟另一个机器人聊天"的上限 —— 两个机器人互相对话会无限自激，
实测每小时能刷几十条，纯烧钱。

## 6. 踩过的坑（给以后的自己）

- **CRLF**：用正则删行内注释时写 `/#.*$/`，在 `\r\n` 的行尾上 `$` 匹配不到 `\r`，
  于是"被注释掉的配置"照样生效。改用 `/#.*/` 才对。
- **注释不该进文件名单纯函数**：负责"运行期重载名单"的那个读取函数当时连注释都没过滤，
  手滑在名单里写一行注释，就能把一个号塞进白名单。两条路必须走同一个解析函数。
- **PowerShell 脚本的编码**：Windows PowerShell 5.1 对没有 BOM 的 UTF-8 文件按 GBK 读，
  中文直接乱码；而给 BOM 加两次会解析失败。带中文的 `.ps1` 必须正好一个 UTF-8 BOM。
- **子进程管道**：在某些受限环境下 `child_process` 用管道抓输出会 EPERM，
  重定向到临时文件再读反而稳。
- **日志文件被占用**：日志是另一进程在写的，用 `ReadAllLines` 会打不开，
  必须用 `FileShare.ReadWrite` 打开。字节偏移量记账也要在同一把读锁里做。
